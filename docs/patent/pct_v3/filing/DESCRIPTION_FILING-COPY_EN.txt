DESCRIPTION

Title of the invention: Dual-use point-cloud representation with embedded explainability

TECHNICAL FIELD

[0001] The present disclosure relates to the production of a task output by a machine learning model and to the production of data explaining that output. More particularly, the disclosure relates to computer-implemented methods in which a point cloud (106) representation produced by a context encoder (102) serves as the single source of both the task output and the explanation data, to computers configured to carry out such methods, and to non-transitory computer-readable recording media carrying instructions executable thereon.

[0002] The disclosure finds application in edge computing, financial transaction classification, machine health monitoring and text processing, that is, in systems in which the explanation of an output decision is subject to an auditable cost or obligation.

[0003] The disclosure carries no assertion that the accuracy of one class of model is higher than that of another class of model. The subject matter defined by the appended claims concerns the generation of task output data and explanation data from the same trained representation, without a separate explanation model and within a transportable package.

BACKGROUND ART

[0004] A prevailing approach in explainable machine learning is to generate the explanation by a post-hoc tool: alongside a trained classifier, a separate attribution tool operating on the input features is run, so that the task output and the explanation originate from different systems. Three technical gaps are observed in working prototypes built on that approach.

[0005] First, the stability of a post-hoc attribution is limited by retraining itself. On the same architecture retrained with five separate training seeds on a fixed test subsample of 400 records, a tree-based post-hoc attribution tool, which is a second system and not the interpretation engine (120) of this disclosure, of installed version 0.54.1 produced a first-rank stability of 0.1025 for the attribution ranking, a Jaccard similarity of 0.43405 for the top-three set, and a Spearman correlation of 0.65105 for the attribution ranking.

[0006] On the same data and the same five seeds, the stability of a nearest-region label derived from the geometric representation of the model itself, defined as the fraction of test records whose label matches the reference-seed label in all retrains, was 0.325. The two sets of figures are not the same quantity: the first set describes an attribution ranking, the second describes the persistence of a label across retrains. No ratio and no superiority is asserted between them. The gap is that a post-hoc attribution yields a quantity that is less stable than the model itself and whose audit requires an additional step.

[0007] Second, the explanation requires a separate software stack on the edge device: running a post-hoc attribution tool adds a further tool and a further computation step beside the deployed model. In one recorded prototype, over the same five training seeds, the fit-and-encode path of the geometric representation, which also produces the explanation data, averaged 0.35445423298515377 seconds per seed, and the path that retrains the tree model and runs the post-hoc attribution averaged 0.7402620668290183 seconds per seed. These two figures are durations of two different work sets; no general complexity ratio is derived from them. The recorded fact is that a post-hoc explanation carries an additional fitting and attribution step.

[0008] Third, a drift audit also requires a separate instrument: monitoring the shift of region shares over time is derived from externally defined feature windows rather than from the structure of the representation, so a second monitoring pipeline has to be installed in order to measure the shift.

[0009] The common cause of these three gaps is that the explanation data is not present in the representation itself but is attached to the representation from outside as a second system.

DISCLOSURE OF THE INVENTION

[0010] According to one aspect, a computer-implemented machine learning method processes a task input (100) with a context encoder (102) to produce context-encoded representations, wherein the task input consists of one of an ordered sequence of tokens and a plurality of measured field values of a tabular record, and represents each context-encoded representation as a point in a D-dimensional space, thereby constructing a point cloud (106) of N points; computes point features (300) for points and pair-geometry features (302), derived from geometric quantities dependent on the positions of the two points of a pair, for point pairs; combines both feature sets into a single set representation by a symmetric set aggregation (112) independent of the input order of the points and of the pairs; and obtains a task output (118) from a reader (116) operating on a reader input, wherein the set representation derived from the context-encoded representations constitutes that reader input.

[0011] Explanation data is produced by applying at least one of three explanation operations to the point cloud of the trained model that produced the task output itself, namely a point-removal effect (122), region naming (124) and region shift (126), without a separate explanation model, a separate explanation training or a separate explanation input. The task output and the explanation data are presented jointly, via an output interface (128), as outputs derived from the same set representation of the same trained model.

[0012] In further aspects, D is selected as an integer between 3 and 64; the pair-geometry features comprise a difference vector (204), a pair distance (206) equal to its Euclidean norm, an angular similarity (208) between the two point vectors and the norms of both points; the symmetric aggregation applies max-pooling over the points and average-pooling (218) over the pairs and combines the results with a concatenation layer (308); N follows the context length of the task input and unfilled context positions and the pairs formed by them are excluded by a mask signal.

[0013] In further aspects, the point-removal effect masks a selected point, re-runs the reader and records the resulting logit difference as contribution data, with the masked cloud variants (406) supplied jointly as one batch input (414) so that the contributions of N points are obtained in N+1 forward passes; region naming partitions set representations or point cloud states by a centroid-based clustering operation and assigns each region a human-readable label built from at least one symbol of a frequency ranking of the input symbols of the records assigned to that region; region shift compares region point shares between a reference data group and a comparison data group and quantifies the difference with a probability distribution divergence measure, marking as an emerging region a region whose share is below a lower threshold in the reference distribution and above an upper threshold in the comparison distribution.

[0014] In further aspects, at least one parametric layer of the reader is represented in INT8 integer quantization and a single self-contained deployment package carries the quantized weights, namely INT8 quantized weights (704), a quantization table (706) mapping input values to model input identities and a resolution table (708) mapping the model input identities to human-readable input labels, so that both the task output and a human-readable form of the explanation data are produced on an edge device; the task input may be a text of several sentences, encoded as sentence cloud states (802) and slid into neighbouring window cloud states (804) by a fixed window size and a fixed stride and processed by a window-geometry encoder (806); and the pair computation may be replaced by global set statistics comprising maximum, minimum, mean and standard deviation pooling together with a cloud centre and a centre deviation, so that the computational cost is proportional to the number of points.

[0015] In further aspects, a training step updates parameters of the reader (116) by gradient-based backpropagation and updates point positions of the point cloud (106) without computing gradients, by zeroth-order accept and revert operations based on the measured change of a task loss caused by a candidate point position.

[0016] According to further aspects, a computer system comprising at least one processor and a memory holds the corresponding modules, namely a context encoder module (102), a point projection module (104), a pair-geometry encoder (110), an aggregation module (112), a reader (116), an interpretation engine (120) operating on the same point cloud (106), and an output interface (128); and a non-transitory computer-readable recording medium stores instructions causing a computer to carry out the corresponding steps, including the joint recording of the task output and the explanation data.

[0017] The technical effect is expressed on measured axes, with the measurement conditions stated. The footprint of the package delivered to the edge device for the tabular task fell from 528.9 KB in 32-bit floating point format to 138.2 KB in INT8 format. Latency of the INT8 reader was 0.015912843984551728 ms per transaction at the 50th percentile and 0.017278228622744793 ms at the 99th percentile over 2000 transactions, at 62845.10641151401 transactions per second. The explanation cost is bounded because the point-removal effect requires N+1 forward passes and the pair computation grows with the square of the number of points: the multiply-accumulate count per transaction was 2522200 for 13 active points and 34091488 for 50 active points.

[0018] The accuracy cost of quantization is measured and accepted as a boundary rather than omitted: on a naturally distributed held-out test set of 4700000 rows containing 6110 fraudulent records, at a base rate of 0.0013, the area under the receiver operating characteristic curve was 0.9450745846153957 in 32-bit floating point format, 0.9364812440872093 with per-tensor INT8 quantization and 0.9367113790742326 with per-channel INT8 quantization, the differences being -0.008593340528186388 and -0.008363205541163099 respectively. Because the explanation data is derived from the region of the representation itself, the stability of the explanation across five retraining seeds is auditable as a single figure, namely the region-label stability 0.325.

[0019] The point positions of the cloud are updated without gradient computation: a candidate position is generated for a point, the task loss is measured with the candidate on the same mini-batch, the candidate is accepted when its loss lies below the base loss by a threshold, otherwise the position is reverted to its previous value and the search interval is narrowed on the candidate side.

BEST MODE FOR CARRYING OUT THE INVENTION

[0029] The following describes the best mode currently contemplated for carrying out the invention; the variants described in paragraph [0065] are alternatives within the same teaching. A chain schematized in FIG. 1 comprises, in order, a task input (100); a context encoder (102) processing the task input (100); a point projection (104) mapping each context-encoded representation into a point of a point cloud P (106) held in a D-dimensional space; a pair-geometry encoder (110) computing features for points and for point pairs; an aggregation module (112) combining those features into one set representation; a reader (116) producing the task output (118) from the set representation; an interpretation engine (120) producing explanation data from the same point cloud (106); and an output interface (128) presenting the task output (118) and the explanation data jointly.

[0030] Two features of this architecture are structural. The representation is processed as a set: the input ordering is not carried into the aggregation, and points corresponding to context-unfilled positions, together with the pairs formed by such points, are disabled by a mask signal. The interpretation engine is not a separate model; it re-runs the forward pass of the reader that produces the task output with the points of that same cloud modified. The explanation is therefore a second use of the representation rather than a second system attached to it.

[0031] The task input arrives in two forms. For an ordered token sequence, the representation produced by the context encoder at each position is projected into a D-dimensional vector and the number N of points equals the context length. For a tabular record, the measured field values of the record are themselves the points of the cloud of that record, so the number of fields determines N and thereby the number of pairs.

[0032] In the recorded implementation examples the dimension D was chosen per task domain: D = 8 with a cloud state size of 128 for a tabular fraud task; D = 32 and D = 64 for two compared configurations of a language task; and an embedding size of 48 for a machine health task. The selected values of D lie between 3 and 64. In the tabular embodiment the number of model input identities was 221, the number of narrowed point positions 214 and the number of active points K 13.

[0033] As schematized in FIG. 2, the pair-geometry feature of a pair (p_i, p_j) formed by a first point (200) and a second point (202) is the concatenation (214) of five components: a difference vector (204) between the two point vectors; the pair distance (206), that is the Euclidean norm of the difference vector (204); a cosine similarity (208) between the two point vectors; a norm vector (210) of the first point (200); and a norm vector (212) of the second point (202). The difference vector and the distance carry the relative position of the pair, the cosine similarity carries its angular relation, and the two norm components carry the absolute position of each point with respect to the cloud centre. The resulting pair-feature width (216) is the algebraic sum 3D + 2, which is the pair input width defined in the implementation.

[0034] The aggregation schematized in FIG. 3 has two paths. In the point path the point features (300) are reduced by a max-pooling branch (304) over the points, yielding a result of the max-pooling; in the pair path the pair-geometry features (302) are reduced by an average-pooling branch (306) over the point pairs, yielding a result of the average-pooling; the result of the max-pooling and the result of the average-pooling are collected in one concatenation layer (308) into one set representation (310).

[0035] Masking applies in both paths. In the point path, points corresponding to context-unfilled positions are set to an invalid value before the pooling and the pooled result is cleared by the mask afterwards. In the pair path a pair counts as valid only if both of its ends are valid; the features of invalid pairs are zeroed and the average is normalized by the number of valid pairs alone, so that unfilled positions contribute no numerical value to the set representation. Since both poolings are operations over a set, the set representation is independent of the numbering order of the points, which keeps the representation defined for a tabular record whose fields carry no ordering.

[0036] The set representation is supplied to the reader (116). In a language task the reader produces a probability distribution of a next token, with the forward pass defined together with an attention mask, and the cloud state is taken from the cloud encoder. In a tabular task the reader produces a class assignment score, and the explanation step is built on the logit of the same reader. The quantity on which the explanation rests is therefore the output of the same reader that produces the task output.

[0037] In the variant schematized in FIG. 8 the task input is a text of several sentences and the context encoder operates in three tiers. In the first tier each sentence is encoded as a sentence cloud state. In the second tier consecutive sentence cloud states are slid by a fixed window size and a fixed stride to derive neighbouring window cloud states; a window size of 5 and a stride of 2 are defined in the implementation. In the third tier geometric quantities between windows is collected by a window-geometry encoder (806) and the resulting multi-sentence set representation (808) is supplied to the reader (810). The fixed window size is a second design knot bounding the growth of the number of pairs: the number of pairs within a window scales with the square of the window size and the number of windows scales with the sentence count divided by the stride.

[0038] The dashed path of FIG. 3 is a variant replacing the pair computation. Instead of pair-geometry features and average-pooling over pairs, global set statistics (312) of the point cloud are computed, comprising maximum, minimum, mean and standard deviation pooling over the point dimensions together with the cloud centre and the centre deviation. Because no pair computation is performed, or it is performed approximately, the cost is proportional to the number of points.

[0039] The cost bound that motivates this variant is visible in the pair path: raising the number of active points from 13 to 50 raised the multiply-accumulate count per transaction from 2522200 to 34091488. The measured ratio of the multiply-accumulate counts is 13.5 and the square of the ratio of the point counts, (50/13)^2, is 14.8, which is consistent with a quadratic growth of the number of pairs. N is therefore bounded by the context length of the task input (100), and on an edge target the global-statistics path may be selected instead of the pair path.

[0040] In the first explanation operation schematized in FIG. 4, the point cloud from which the task output was produced is preserved and a selected point is temporarily disabled. A point cloud is produced from the input units; the reader (116) is run in the unmasked state to obtain a base output (404); the point concerned is set to a zero value in a copy of the cloud and its mask is closed, which yields a masked cloud variant (406); the reader (116) is re-run on the masked path (408) with the masked cloud; and the contribution (412) of that point is recorded as the base output (404) minus the masked output (410). The definition is recorded as a logit difference, namely the base logit minus the logit with the point concerned masked.

[0041] The same operation runs on the quantized deployment: masked cloud variants (406) are prepared as a single batch input (414), each variant mask being built by closing the position concerned, and the INT8 inference session is invoked once; the contribution (412) is produced as a logit difference. The N+1 forward passes for N points are thereby reduced to one batched call.

[0042] The interpretation of this operation is bounded as recorded in the prototype: the quantity produced is a removal sensitivity, not a single-additive attribution, and because of the pair computation the contributions are not additive. A contribution is therefore presented as the measured change of the decision when that point is removed, and not as the share of one input feature. In one pilot the input units are ranked by the product of the mean absolute logit contribution and the square root of the observation count.

[0043] In the second explanation operation schematized in FIG. 5, the set representations or point cloud states (500) of a plurality of records are partitioned into geometric regions by a centroid-based clustering operation (502); KMeans is used in the prototype, with eight regions in the complaint embodiment. In a classification embodiment the regions may alternatively be defined as prototypes taken as the means of the class representations of the training set, a definition established on training data only.

[0044] Each region receives a human-readable region label (506) by combining at least one symbol selected from a frequency ranking of the input symbols of the records assigned to that region; the first eight ranked symbols are used in the prototype. Measured labels, recorded with sub-word boundary markers, are "credit report information" for two distinct regions and "credit report consumer" for a further region.

[0045] A verifiable boundary of region naming is recorded: two geometrically distinct regions may carry the same human-readable label, as in the measured example in which two separate regions share the label "credit report information". A region label is therefore not an identity by itself; the audit is performed jointly with the region index.

[0046] In the third explanation operation, whose measurements are shown in FIG. 6, the point shares of the same geometric regions are compared between a reference data group and a comparison data group, and the difference between the share distributions is quantified by a probability distribution divergence measure. Two measures are used: a total variation measure defined as half the sum of the absolute differences of the region shares, and a Kullback-Leibler divergence. Regions whose share lies below a lower threshold in the reference distribution and above an upper threshold in the comparison distribution are marked as emerging regions. No drift label is used by definition; the reference is the set of region centres fixed in the training window.

[0047] Measured weekly values, reported against the preceding week, were 0.0903703703703704 total variation and 0.0341397185589417 Kullback-Leibler divergence for the week 2025-02-03/2025-02-09, and 0.02469135802469135 total variation and 0.0018965315544816688 Kullback-Leibler divergence for the following week 2025-02-10/2025-02-16.

[0048] The quantity plotted in panel (a) of FIG. 6, namely in the region point-share shift panel (600), is the difference of region point shares between the training window and the drifted window, measured on a subsample of 20000 records consisting of 14000 training and 6000 drifted records. The measured extremes of the per-region share difference are -0.17 for region 1 and +0.2068 for region 7. The stability of the region assignment under subsampling was also measured: a mean adjusted Rand index of 0.9938922500989028 and a mean rank correlation of region shares of 1.0.

[0049] Panel (b) of FIG. 6, namely the setting shift panel (602), measures the effect of a setting shift on the alarm rate. On held-out healthy records that were not disturbed, the alarm rate was 0.011723329425556858; after a constant shift vector [6.0, 6.0, -6.0] was applied to three measured fields, the alarm rate was 0.02813599062133646, recorded as a ratio of 2.4. The alarm threshold is the distance value computed from the 0.95 quantile of the training distribution, namely 8.460468292236328, and the number of held-out healthy records is 853.

[0050] In the deployment schematized in panel (b) of FIG. 7, the parametric layers of the reader are quantized to INT8 integer format and the reader (116) carries a distribution store holding, in one self-contained deployment package (904), three things: the quantized model weights, namely INT8 quantized weights (704), a quantization table (706) mapping input values to model input identities, and a resolution table (708) mapping the model input identities to human-readable input labels. The recorded components of the deployment package are a quantized inference model of 548.4 KB, a quantization table of 5.4 KB, a resolution table of 16.5 KB and 221 resolution entries. The mappings are recorded as follows: raw rows become identities through the quantization table, and identities become human-readable labels through the resolution table.

[0051] The task output and the human-readable explanation thus leave the same package on the edge device: the point-removal operation is executed on the INT8 session and the label of the masked input identity is read from the resolution table. In the self-test of the package, over 19963 rows, the largest absolute difference against the 32-bit floating point reference was 1.2814998626708984e-06, the 99th percentile absolute difference was 8.401274840252881e-07, and the throughput was 26473.303851652894 transactions per second.

[0052] The footprint budget is also tracked by counting unused parameters: in the tabular deployment the number of parameters belonging to the language model and unused in the package was recorded as 8392. This record shows in an auditable manner which part of one and the same architecture is carried for which task; it contains no measurement of multi-task performance.

[0053] Training has two parts. The weights of the reader are updated by gradient-based backpropagation. The positions of the point cloud are updated without computing a gradient: a candidate position is produced for a point position, the task loss is measured with the candidate on the same mini-batch, the candidate is accepted if its loss falls below the base loss by a threshold, and otherwise the position is reverted to its previous value while the search interval is narrowed on the candidate side. This zeroth-order acceptance and reversion requires no backpropagation for updating point positions.

[0054] In a first measured example, a tabular classification task produced a fraud score from the eight field values of a credit-card transaction record, with D = 8, a cloud state size of 128 and K = 13. Training on a 100000-record sub-slice containing 130 fraudulent records, at a base rate of 0.0013, completed in 2852.3 seconds and produced, in this configuration, an area under the receiver operating characteristic curve of 0.9351451502337654 and a recall of 0.7307692307692307.

[0055] The boundary of this example is recorded. In a full-scale comparison on the same data family the test set holds 4716078 rows, and two further comparison models produced higher areas under the curve: 0.9933922442255942 for a gradient-boosted tree ensemble, 0.9694542323758608 for a transformer-based tabular model, while a second gradient-boosted tree ensemble produced 0.9364403244701196. No superiority in accuracy is asserted. What this example supports is that a representation which is deliverable to an edge device and which produces its own explanation and region audit yields the same task output beside a high-accuracy tree model.

[0056] In a second measured example the areas under the curve of FIG. 7, panel (a), were taken on a naturally distributed held-out test set whose base rate is preserved: 4700000 rows, 6110 fraudulent records, base rate 0.0013, giving 0.9450745846153957 in 32-bit floating point format, 0.9364812440872093 with per-tensor INT8 quantization and 0.9367113790742326 with per-channel INT8 quantization, with quantization costs of -0.008593340528186388 and -0.008363205541163099. The same measurement is written in rounded form in the run log as 0.9451, 0.9365 and 0.9367.

[0057] The output drift of the quantized model was also measured over 4096 randomly selected QUANN-point proxy inputs: the largest probability difference was 0.3432929813861847, the mean difference 0.008917972445487976 and the 99th percentile difference 0.14572913944721222. This is the measure of an output difference that quantization accepts, per individual decision, for the sake of deliverability. The footprint of panel (b) is the size of the package delivered to the edge device: 528.9 KB in 32-bit floating point format against 138.2 KB in INT8 format, and the quantized inference file of the evaluation artefact is 543.5 KB with a largest absolute difference of 1.0058283805847168e-07 against the floating point reference.

[0058] In a third measured example, two configurations of one training arrangement were compared on a separate held-out set for the choice of dimension: a held-out perplexity of 61.94 for D = 32 and 61.19 for D = 64, a difference of 0.76, with D = 64 recorded as the winner. The protocol is recorded on the same line: 2000 samples, seed 0, row interval [200000, 202000), sequence length 10. These values are the measurement of one dimension choice and are not compared with perplexity values measured under other protocols.

[0059] The boundary is recorded here too. On a common held-out set of 2000 sentences the perplexity was 6.45 for the point-cloud language model and 2.94 for a causal language model baseline, the baseline measuring lower; the compared models hold 20999648 and 22724768 parameters respectively. No superiority in accuracy is asserted for the language task. What the language task supports is that the task output and the three explanation operations are producible from one and the same representation.

[0060] In the multi-sentence hierarchy of FIG. 8 the data was divided in the ratio 80/10/10 with seed 42, and the split was recorded as 159888 training, 19986 validation and 19986 test sentences; the vocabulary was 10000 and the model 12260784 parameters. Training reached a lowest validation loss of 3.2305 and a separate held-out test loss of 3.2318. These are cross-entropy losses, not perplexities, and they are not presented as the same metric as the values of the preceding paragraphs.

[0061] In a fourth measured example the explanation outputs were produced without any separate explanation model. The contribution pilot is a stratified development sample of 827 records containing 27 fraudulent records at a base rate of 0.032648125755743655, and the file records expressly that this sample is not the natural 4.7 million held-out population; the area under the curve measured on this sample was 0.8286111111111112. What this pilot supports is not production accuracy but that contribution data can be produced without a separate explanation model: the contribution is a logit difference, a positive value means that the input unit supports the fraud prediction, and the recorded caveat states that the contributions are removal sensitivities and are not additive.

[0062] For region and prototype labelling, the held-out accuracy of a nearest-prototype assignment against prototypes fitted in training was 0.75 on a graph transaction data family whose test set holds 400 nodes of which 40 are illicit, with per-class accuracies of 0.7833333333333333 and 0.45. The prototypes are defined as the means of the training nodes only. The recorded boundary states that one-hop graph features are transductive and that the source data carries transaction nodes rather than account identities.

[0063] The state-dependent limit of region purity was likewise measured. In a machine health task the nearest-prototype accuracy on a held-out test set of 1064 records was 0.8167293233082706, and it fell with the degradation stage: 0.9378663540445487 on 853 healthy records, 0.18421052631578946 on 114 intermediate records and 0.64 on 25 records of the critical stage. This is the measured statement that a region label cannot serve alone as audit evidence for degraded states.

[0064] In a fifth measured example the stability of the explanation was audited. On five separate training seeds and a fixed test subsample of 400 records, the region-label stability was 0.325, defined as the fraction of test records whose nearest label matches the reference-seed label across all retrains. The post-hoc attribution path measured under the same protocols yielded three separate quantities: a top-1 rank stability of 0.1025, a top-3 set Jaccard similarity of 0.43405 and an attribution-ranking Spearman correlation of 0.6510458604357529, with a tree attribution tool of installed version 0.54.1. Since these quantities are not the same quantity as 0.325, no ratio and no superiority is drawn between them; the result used by the disclosure is that the stability of the explanation becomes traceable by a single figure without a second instrument independent of the training.

[0065] Further variants are contemplated. In a first variant the pair computation is replaced by global set statistics (312), as described above with reference to the dashed path of FIG. 3, and this path is selected when the number of points has to grow on an edge device. In a second variant the sentence-cloud and window-cloud hierarchy of FIG. 8 is used, in which the task input (100) is a text consisting of a plurality of sentences (800) and the context encoder (102) encodes each sentence of the plurality of sentences as a sentence cloud state (802). In a third variant the point positions are updated by the acceptance and reversion described above while the reader is trained by backpropagation; the cost limit of this third variant was also measured, since a zeroth-order update requires one forward pass per candidate and was therefore not found practicable on a larger model, so the measurement was made at a smaller scale of the same architecture.

[0066] In that smaller-scale measurement the held-out perplexity was 1045.03 for an untrained baseline, 563.45 for training by backpropagation and 1016.30 for the zeroth-order update, on 6000 training and 500 evaluation sentences, a sequence length of 8 and a vocabulary of 1024 pieces. The zeroth-order variant produced a higher perplexity than backpropagation training; it is sought for its provision of a point update that requires no backpropagation and not for an accuracy assertion.

[0067] The following boundaries apply to the whole of the above description. The figures were measured in single configuration and corpus combinations, for example D = 8, a cloud state size of 128 and K = 13 for the tabular task; no generalization beyond those combinations is asserted. The accuracy cost of the INT8 transition was measured and its acceptance is the basis of the deliverability statement. The explanation data is not an additive attribution. A region label is not an identity. An emerging-region mark is defined as a criterion; no emerging-region event was recorded in the measured complaint drift, and the mark is therefore claimed as a criterion and not as an observed occurrence. No area of this description asserts superiority of accuracy over tree ensembles, transformer-based tabular models or causal language models.

INDUSTRIAL APPLICABILITY

[0068] The present disclosure is directly applicable in systems that run on an edge device and whose decisions are subject to an audit requirement. In financial transaction classification the INT8 deployment package (904) is delivered with a footprint of 138.2 KB, produces a latency of 0.015912843984551728 ms per transaction and a throughput of 62845.10641151401 transactions per second, and the input identities on which a declined transaction rests are read from the resolution table as human-readable labels.

[0069] In machine health monitoring the region shift shows, without any label, that a setting change moved the alarm rate from 0.011723329425556858 to 0.02813599062133646. In text processing the multi-sentence hierarchy is trained on a separate 80/10/10 split with seed 42, and the region labels are produced from ranked human-readable symbols of the complaint subjects of the records forming each region.

[0070] The components required for production are standard: a processor and a memory, a reader whose weights are stored in INT8 format, two mapping tables, and an interpretation step that re-runs the forward pass with masked inputs. Since no separate explanation training, no separate explanation model and no separate explanation input are required, the explanation capability is versioned and audited together with the model, which is the property relied upon in regulated edge deployments such as payment decisioning, predictive maintenance and document triage.

ADDITIONAL ENABLING DETAIL FOR CLAIMED ELEMENTS

[0071] The task input (100) is supplied to the system in one of the two recorded forms and reaches the context encoder (102) unchanged. In the token-sequence form the input is a sequence of sub-word pieces drawn from a vocabulary of recorded size 1024 pieces or 10000 pieces, and the recorded sequence lengths are 10 and 8. In the tabular form the input is a record of 8 measured field values of a credit-card transaction. A third use, a text of a plurality of sentences, is processed by the same task input (100) through the tiers described above with reference to FIG. 8. Where the context encoder (102) yields no output at a context position, that position is unfilled and the mask signal removes the corresponding point from the aggregation.

[0072] The context-encoded representations are the per-position outputs of the context encoder (102); each of them becomes one point of the cloud through the point projection (104) and nothing else is fed to the aggregation module (112). In the recorded language configurations the context-encoded representation is a vector of dimension D = 32 or D = 64 produced with a cloud state size of 128; in the recorded tabular configuration it is a vector of dimension D = 8 produced with the same cloud state size of 128. The number of context-encoded representations delivered to the point projection (104) per record equals the number of positions the context encoder (102) covers, so the encoder output and the cloud share one dimension and no further representation is computed for the explanation operations.

[0073] The point in the D-dimensional space is produced by the point projection (104), which maps each context-encoded representation onto one vector of the space and writes no per-point index into that vector. The bounds recorded for the space are the bounds stated above: D is selected as an integer between 3 and 64, the recorded values being 8 for the tabular task, 48 as the embedding size of the machine health task, and 32 and 64 for the two compared language configurations. Because the vector carries no index, the same projection defines a point both for a position of a token sequence and for a field of a tabular record.

[0074] The ordered sequence of tokens enters the task input (100) as sub-word pieces of a recorded vocabulary of 1024 pieces or of 10000 pieces and with recorded sequence lengths of 10 and 8; in both recorded protocols the piece order is the order in which the pieces were cut from the text. The number N of points equals the context length of the sequence, and positions the context encoder (102) leaves unfilled are closed by the mask signal so that neither their points nor the pairs formed by them contribute a numerical value to the set representation. The ordering is used only to select the context-encoded representation of a position; it is not used by the aggregation module (112).

[0075] The tabular record supplies its measured field values as the points of its own cloud, so the field count determines N and thereby the number of pairs, and the record carries no ordering of its fields. The recorded record holds 8 measured field values of a credit-card transaction; in the same recorded embodiment the number of narrowed point positions was 214 and the number of model input identities was 221, so the number of fields, the number of positions and the number of identities are three separate quantities that the system keeps separately. Because the field ordering is not carried into the aggregation module (112), two records that differ only by a permutation of their fields yield the same set representation.

[0076] The point cloud (106) is held as one batch tensor in which each row is the vector of one point and each slice is the vector of the point of one record; the number of rows of a record is N and the width of a row is the dimension D. The interpretation engine (120) keeps the cloud from which the task output (118) was produced and sets a point to a zero value only in a copy of it, which is the masked cloud variant (406). With the recorded tabular configuration, namely D = 8 with a cloud state size of 128 and K = 13 active points, one cloud of one record therefore occupies a matrix of the stated row count and the stated width, and the point-removal effect (122) multiplies that occupancy by the copies it builds rather than by a second model.

[0077] The input order of the points is excluded from the aggregation module (112) because both pooling operations are operations over a set: the max-pooling takes a component-wise maximum over rows and the average-pooling takes a sum over valid pairs divided by a count, and neither operation reads a per-point index. The exclusion holds also for the pairs: the pair-geometry feature of a pair is computed from geometric quantities of its two points and the average over pairs normalizes by the number of valid pairs alone, so swapping two points changes neither which quantities are computed nor the value of the set representation. This is what keeps the representation defined for a tabular record whose fields carry no ordering.

[0078] The reader (116) takes as its reader input the set representation and nothing else: neither the cloud nor any intermediate point or pair feature is routed to it. Its forward pass is defined together with an attention mask, which is the route by which the context-unfilled positions of the token-sequence form stay out of the task output (118), and the cloud state is taken from the cloud encoder. The reader (116) is the module whose forward pass is re-run by the interpretation engine (120) on the masked path (408), so the explanation quantity and the task quantity are read from one and the same set of weights.

[0079] The probability distribution of a next token is the task output (118) of the reader (116) in the language task; it is produced from a logit per vocabulary piece and the training signal is the cross-entropy of that distribution against the observed piece. The recorded held-out perplexities of this output are 61.94 for D = 32 and 61.19 for D = 64, with the protocol recorded on the same line as 2000 samples, seed 0, row interval [200000, 202000) and sequence length 10. The values 3.2305 and 3.2318 recorded for the multi-sentence hierarchy are cross-entropy losses and are not perplexities of this distribution.

[0080] The class assignment score is the task output (118) of the reader (116) in the tabular task: a single logit for the positive class of the transaction, from which the fraud decision is taken. The explanation step reads the same logit, which is why the contribution (412) is defined as a difference of that logit rather than of a separately trained score. In the recorded configuration with D = 8, a cloud state size of 128 and K = 13, training on a 100000-record sub-slice containing 130 fraudulent records at a base rate of 0.0013 produced an area under the receiver operating characteristic curve of 0.9351451502337654 and a recall of 0.7307692307692307, and the quantized reader produced its decision at a 50th percentile latency of 0.015912843984551728 ms per transaction.

[0081] The same trained model is the model whose weights are held in the deployment package (904): the explanation operation is applied to those weights and not to a surrogate fitted beside them. In the recorded deployment the explanation operation ran on the quantized inference model of 548.4 KB that is one of the components of the delivered package, and its forward pass is the pass that produced the task output (118) of the same record. The consequence relied upon is a versioning property: because no second model, no second training run and no second input exists, the explanation data cannot be of a different version than the decision it explains, and the package of 138.2 KB carries both.

[0082] The Euclidean norm of the difference vector is computed in the pair-geometry encoder (110) as the scalar pair distance (206) of the pair, from the difference vector (204) between the vector of the first point (200) and the vector of the second point (202). The pair distance (206) contributes one component to the pair-feature width (216), which is the algebraic sum 3D + 2; the difference vector (204) and the pair distance (206) carry the relative position of the pair, while the two norm components carry the absolute position of each point with respect to the cloud centre. No quantity other than these five components enters the concatenation (214).

[0083] The result of the max-pooling is the output of the max-pooling branch (304) of the aggregation module (112), obtained as the component-wise maximum over the rows of the matrix of the point features (300). Its width is the point-feature width and it is therefore independent of the number N of points, which is the property that keeps the reader input the same size for two records with different numbers of active points. Unfilled positions are set to an invalid value before the pooling and the pooled result is cleared by the mask afterwards. The max-pooling branch (304) is the point path of FIG. 3 and its result is one of the two inputs of the concatenation layer (308).

[0084] The result of the average-pooling is the output of the average-pooling branch (306), obtained by summing the pair-geometry features (302) of the valid pairs and dividing by the number of valid pairs alone, so a pair with an invalid end contributes neither a numerator nor a denominator. Its width is the pair-feature width (216). The result of the max-pooling and the result of the average-pooling are not added, averaged or interleaved: they are gathered by the concatenation layer (308) in one vector, which is the one set representation (310) supplied to the reader (116).

[0085] The context length of the task input (100) bounds N because the number of pairs, and with it the cost of the pair path, grows with the square of N. The recorded pair cost is the following: raising the number of active points from 13 to 50 raised the multiply-accumulate count per transaction from 2522200 to 34091488, the measured ratio of the counts being 13.5 against 14.8 for the square (50/13)^2 of the point-count ratio, which is consistent with quadratic growth. The bound is therefore an input-side bound rather than a design preference: the operator fixes the context length, and on an edge target where the bound would have to be relaxed, the global set statistics (312) replaces the pair path so that the cost becomes proportional to the number of points.

[0086] The emerging region is defined by two numeric conditions that the interpretation engine (120) evaluates per region: the share of the region in the reference distribution lies below a lower threshold and its share in the comparison distribution lies above an upper threshold. The region shares are taken from the region statistics (504) and the two distributions are compared by the total variation measure and by the Kullback-Leibler divergence; the recorded weekly values were 0.0903703703703704 total variation and 0.0341397185589417 Kullback-Leibler divergence for the week 2025-02-03/2025-02-09 and 0.02469135802469135 and 0.0018965315544816688 for the week 2025-02-10/2025-02-16. No emerging-region event was recorded in that drift, so the mark is stated as a criterion and is not asserted as an observed occurrence.

[0087] The plurality of sentences is counted before encoding: the recorded hierarchy was divided in the ratio 80/10/10 with seed 42, recorded as 159888 training, 19986 validation and 19986 test sentences with a vocabulary of 10000. The sentence count sets the number of sentence cloud states (802) and, after the window step, the number of windows, which scales with the sentence count divided by the stride. The recorded training of that hierarchy reached a lowest validation loss of 3.2305 and a separate held-out test loss of 3.2318, both being cross-entropy losses.

[0088] The sentence cloud state (802) is produced in the first tier by the context encoder (102) for one sentence at a time, in the same point format as the other clouds of the chain, so a sentence cloud state carries a point per encoded position of that sentence and the mask signal closes its unfilled positions. Its input is one sentence of the plurality of sentences (800) and its output is consumed twice: by the second tier, which forms the neighbouring window cloud states (804), and by the region operations of the interpretation engine (120), which read the cloud states of the records of a data group.

[0089] The fixed stride is the step by which the window of fixed size is advanced over the ordered list of sentence cloud states (802) to derive the neighbouring window cloud states (804); a window size of 5 and a stride of 2 are defined in the implementation. A stride smaller than the window size makes adjacent window cloud states share sentences, which is what allows the geometric quantities between windows to carry the continuity of the text; a stride equal to the window size would remove that overlap at the price of discarding the boundary sentences from the comparison. The number of pairs inside a window scales with the square of the window size and the number of windows with the sentence count divided by the stride, so the two constants together bound the cost of the second tier.

[0090] The multi-sentence set representation (808) is produced by the window-geometry encoder (806), whose input is the set of neighbouring window cloud states (804) and whose output is one vector per record, of the same reader-input format as the single-window set representation. The encoder collects the geometric quantities between windows in the same manner as the pair-geometry encoder (110) collects them between points, and no per-window index is written into the vector, so the third tier receives the reader (810) an input that is independent of the order in which the windows were visited.

[0091] The cloud centre is used at two points of the chain. In the pair-geometry encoder (110) the two norm components of the concatenation (214) carry the absolute position of each point with respect to the cloud centre, which is the information a difference vector alone cannot express. In the global set statistics (312) the same centre is computed together with the maximum, minimum, mean and standard deviation pooling over the point dimensions and with the centre deviation, and these quantities replace the pair-geometry features (302) and the average-pooling (218) of the pair path, so that the cost is proportional to the number of points.

[0092] The training of the reader by gradient-based backpropagation updates the weights of the reader (116) through the same forward pass that produced the task output (118), and it is the only gradient-based part of the training; the parametric layers of the reader may then be represented in INT8 integer quantization for delivery. The recorded comparison of the two training paths was made on 6000 training and 500 evaluation sentences with a sequence length of 8 and a vocabulary of 1024 pieces, and produced held-out perplexities of 563.45 for training by backpropagation and 1016.30 for the zeroth-order update against 1045.03 for an untrained baseline.

[0093] The candidate point position is produced for one point position at a time, on the same mini-batch on which the base task loss was measured. The candidate is accepted when its loss lies below the base loss by a threshold; otherwise the position is reverted to its previous value and the search interval is narrowed on the candidate side, so the candidate never needs a gradient and the search contracts around the accepted side. The cost of the mechanism is one forward pass per candidate evaluated on the batch, which is the reason the recorded measurement of this path was made at the smaller scale of the same architecture rather than at the scale of the delivered package.

[0094] The computer system comprises at least one processor and a memory holding the context encoder module (102), the point projection module (104), the pair-geometry encoder (110), the aggregation module (112), the reader (116), the interpretation engine (120) and the output interface (128). The input and output of each module are the quantities stated above: the pair-geometry encoder (110) takes points and pairs and returns the pair-geometry features (302); the aggregation module (112) takes the point features (300) and the pair-geometry features (302) and returns the set representation; the interpretation engine (120) takes the cloud of the record and returns the contribution (412), the region label (506) and the region-share comparison. No module reads a store that belongs to a second model.

[0095] The at least one processor executes the forward pass of the reader (116) and executes the N+1 forward passes of the point-removal effect (122) as one batch input (414) of masked cloud variants (406), so the interpretation run is one invocation of one session rather than a sequence of runs. The recorded tabular embodiment shows how the two widths of that execution differ: the number of model input identities was 221 while the number of narrowed point positions was 214, so the input width presented to the processor and the width of the cloud it reads are two separate quantities fixed by the input mapping and by the cloud definition respectively. The recorded latency of that execution on the quantized reader was 0.015912843984551728 ms per transaction at the 50th percentile and 0.017278228622744793 ms at the 99th percentile over 2000 transactions.

[0096] The instructions configure the system to carry out the steps in the recorded order: constructing the cloud from the task input (100), encoding, computing the point features (300) and the pair-geometry features (302), aggregating them into the set representation, reading the task output (118), re-running the reader (116) with a masked cloud variant (406) and recording the contribution (412), comparing region shares between two data groups, and presenting the task output and the explanation data jointly through the output interface (128). The instruction set writes no explanation datum to a store that the reader (116) reads, so the joint presentation is produced at the output interface (128) and not by feeding the explanation back into the decision path.

[0097] The distribution store holding the per-identity contribution data is the distribution store of the deployment package (904). [0098] The independence of the input order is the property on which the further method variant rests: the aggregation module (112) applies max-pooling over the points and average-pooling (218) over the pairs, both of which are operations over a set, so the set representation is a function of the set of context-encoded representations rather than of the order in which the task input (100) listed them. The pair-geometry feature of a pair is symmetric in the sense that it is built from geometric quantities of the two points, and the mask signal selects which pairs enter the average without reference to a pair index. The practical consequence is the tabular case: a record whose fields carry no ordering produces the same reader input, and therefore the same task output (118) and the same explanation data, under any permutation of its fields.
